## 一、先给你一个可执行的判断

1. **不要因为旧线性头失败，就断言完整连接组没用；也不要继续只加旧路线时长。** 历史结果确实没有完成 full-entry，但只覆盖一次训练、两个冻结验证 case。
2. **先建立 A5 像素 PPO 的真实可学习基线**，再试 A4 运动视觉、A6 像素 DQN。资源允许后跑 A1、A2，再筛 A3 候选；A7 作为效果优先的混合路线。
3. **性能与连接组因果贡献分开回答。** 最终像素最好，就用像素；混合最好，就用混合。都不能直接称“生物果蝇学会打游戏”。
4. **先短验收、后单路线 2 小时筛查、再把入围路线扩到累计 8 小时。** 这不是七条路线总共两小时。A0 是历史锚点，不必重新花两小时复跑。
5. **suite 目前不能拿来直接开跑。** 自带清单的 `ram_gib`、`commit_gib` 是 `null`，这是刻意 fail closed，不是零需求。必须先获得真实峰值，填入预算，并释放足够系统内存。不要用 0 或随便编一个数字绕过门禁。

## 四、五层接口：该在哪里改、如何定位失败

### 第 1 层：真实游戏、策略输入与奖励接口

复用 `flyrl.environment.GameEnv/ActionCodec`。每次真实 `env.step` 是一个游戏 tic，返回 RGB、终止边界及真实末帧；遥测只用于奖励、课程统计和评估，不送入策略。当前 v2 配置校验只支持 `task=corridor`，不能因为部分函数留有 combat 分支，就称 combat 已端到端支持。

先查：是否真的移动、转向、碰墙和触发出口；奖励分项是否与行为一致；超时 truncation 是否保留真实 final observation。不要用累计 shaped return 代替出口率。

### 第 2 层：感觉编码接口

脑路线把每 tic RGB 映射到受体亮度向量。`agc_motion`、`raw` 复用旧视觉接口；`adapt` 是约 200 ms 因果基线适应；最新 `contrast` 已实现为线性光灰度上的 **9×9空间局部Weber对比度**：积分图求局部均值、边缘复制，经过tanh映射后重新sRGB编码，再沿原Vision线性化/UV采样路径进入受体。这是实际空间局部变换，不是全局受体均值归一化；仍是工程单通道驱动，不能称已生理复现 ON/OFF 神经通路。

A4 在人工视觉分支真正保留 gray、ON、OFF 三路：ON=max(当前灰度−前一 tic 灰度,0)，OFF 为负差分的正部。A5/A6/A7 像素支路是完整视野双线性缩放的 84×84 灰度。

### 第 3 层：完整全脑动力学接口

A1/A2/A3/A7 使用完整图，逐 tic 推进 `FrozenBrain`，不截取小子图、不反向传播全图、不把图塞入 GPU。35 Hz 下每 tic 约 28.57 ms 脑模拟；动作保持期间仍读每个中间 RGB 并推进脑/trace，不能用一次长 `brain.step` 冒充多个短步严格等价。

默认动力学 scale/bias/threshold 为 1.5/6/−48；另有 1/12/−45 和 1/4/−48。v2 拒绝低于静息电位 −52 的阈值。诊断中 `integration_set` 是累计积分集合规模，`spiking_neurons` 是当前帧真正放电神经元数，二者不能混用。更活跃不自动更有信息，也不等于更好。

### 第 4 层：特征、历史与归一化接口

A1：246 维×最近四个决策边界，以及四个对应差分，共 **1968 维**。A2/A3/A7：512 桶精确 ID signed hash，经桶人数平方根归一化、50/200 ms trace、保符号 `asinh`，拼接 fast、slow、fast−slow，共 **1536 维**。这是有碰撞的固定身份投影，不是逐神经元无损保留，也不是真实视野坐标。

向量归一化只用 train 布局的固定随机校准轨迹，Welford 在线累计后冻结，标准差下限 .01，标准化特征裁剪到 ±10。不存全脑 raster。归一化、hash 映射和编码语义进 checkpoint；reset 清脑、视觉、trace 和历史，不清冻结统计。

**图像历史当前是最近四个逐 tic 帧，不是最近四个决策帧。** `action_repeat=4` 时四帧覆盖约 114 ms，而不是四个动作周期。首局历史左侧补零，首帧之后逐渐填满；不会跨 episode 借用旧帧。A4 为 12×84×84，A5/A6/A7 像素支路为 4×84×84。

### 第 5 层：动作、学习器与预算接口

默认走廊原六动作，允许停止；可选 `action_set=forward` 只保留前进动作，不根据遥测动态切换。默认每 4 tics 决策一次；代码支持正整数保持长度，但未经短验收不建议偏离计划的 1/2/4。动作保持减少决策/学习调用，不免除全脑逐 tic 成本。

一次实际长度 k 的宏转移采用：`R=Σ gamma_tic^i * r_i`，`D=(1-terminated)*gamma_tic^k`。DQN target 是 `R+D*Q_target(next,argmax Q_online)`，不再额外乘一次 gamma。PPO 的 GAE 使用同一完整 discount；lambda=.95 是 **decision-level**，episode 结束切断递推，truncation 保留末状态 bootstrap。

优先检查 Q/TD/梯度是否有限、是否实际更新、动作是否坍塌、课程是否卡住。源码有 `updates.jsonl` 和 `episodes.jsonl` 等基础日志，但没有把批准计划中的全部特征有效性、常量维度、裁剪率、资源峰值和吞吐诊断都自动汇总成完备仪表盘；正式验收仍需补账。

**重要：A2-2h 与 A3-2h 当前默认设置实际相同。** A3 是候选实验的命名基座，不是凭路线名字就形成另一种机制。不要把二者都长训一次就算独立方法收益；A3 应使用明确变体，且总预算记账。

## 六、默认预算、内存与课程：不要忽略这些限制

### 6.1 时长与计数

所有正式新路线配置继承 `max_game_tics=10000000`，`max_tics=2000`；2h/8h 文件分别设置墙钟 2/8 小时。先到者停止。日志区分 `game_tics`、`decisions`、`brain_ms`、校准 tics、更新和墙钟。`brain_ms` 是累计模拟时间，不是 CPU 墙钟。

- 单路线 2h：筛查预算，不保证学会。
- 单路线 8h：累计扩展预算，不是每条自动追加八小时。
- 七条新路线各 2h：串行训练上限约 14h，另加初始化、checkpoint 和全部评估。
- 七条各 8h：约 56h 训练上限；没有必要在筛查前全开。
- A3 额外八变体各 2h 又是最多 16h，不包含在基础七条中。

墙钟在 pipeline/模型初始化之后开始计入训练计时；校准包含在该计时内。不可中断的一次环境/编码/优化调用和最终持久化会使真实进程耗时超过名义预算。不要把 `wall_s` 当作包含所有加载与保存的进程端到端秒数。

### 6.2 课程

默认 gated：exit→near_turn→entry，只用训练成功统计。最近最多 20 局，至少 10 局、成功率至少 60%、左右各至少两次成功才晋级；后阶段 20% 抽样简单起点。未达到门槛就停在当前阶段，不自动因时间过去而假装掌握。

固定课程另有配置，按累计训练 game tics/`max_game_tics` 的 10%/30%/100% 切换。在 1000 万 tic 上限、脑路线低吞吐的情况下，固定课程可能长期停留在 exit；必须看实际采样日志，不能仅把 gated 改 fixed 就认为覆盖了 entry。

### 6.3 当前默认 replay 与保存峰值

最新 `runner.make_agent` 已将正式入口 DQN 默认 replay 调整为：**向量5000、含图像2000**，显式 `learner.replay_capacity` 可覆盖。注意底层 `DQNConfig` 类自身仍有20000默认；本报告的5000/2000指新runner实际工厂入口。图像以 uint8 保存，但每条转移分别保存 obs/next_obs，未做跨样本帧共享。

仅 A6 默认图像原始数据：2000×2×4×84×84 字节约 **0.105 GiB**，还不含 Python 对象、batch、模型、优化器和 checkpoint 副本。A1 的5000容量按 obs/next float32 粗算约0.073 GiB，A2约0.057 GiB；这些不是进程峰值。

**当前 ReplayBuffer.state_dict 仍会复制完整 replay 到 tensor 列表。** 因此“checkpoint 不复制整个 replay”的计划目标尚不能视为完成；保存时资源峰值必须单独测。PPO 默认 rollout=256 decisions，A4 的图像观测体积又是 A5 的三倍。最新修正后需重新短测，不能拿旧默认下的smoke代替最终验收。本报告任务没有改任何源码或配置。

### 6.4 系统资源门禁

机器为 16 GB RAM、RTX 4060 Laptop 8 GB；CPU 逻辑核心多不代表能同时加载多个完整脑。当前约 2.8 GiB 可用 RAM 甚至小于 3 GiB 系统预留，全脑短跑阻塞，不应硬跑或自动结束你已有进程。

suite 要求每个 run 明确 `ram_gib`、`commit_gib`、`vram_gib`；RAM 必须正、commit 不小于 RAM，CUDA 必须正 VRAM。未知探测值同样拒绝；CPU 显式 `vram_gib=0` 可以不要求 GPU 探测。门禁为：可用 RAM≥3 GiB＋当前批次全部任务 RAM 预算；commit/VRAM 也要覆盖任务之和。

自带 suite 的 RAM/commit 为 null，所以连 plan 都可能在需求校验阶段报错，**这是预期拒绝，不是一个“资源看起来够”的计划**。先人工释放非必需负载、用安全工具记录短跑/保存峰值，再在你自己的正式 suite 清单里填真实测量加余量。软件不会自动替你估出可靠峰值。

默认 CPU，不会因为有 4060 就自动把 CNN 放 CUDA。GPU 可用于学习器，不代表完整脑仿真已 GPU 化。显式并行最多一脑＋一 CNN，绝不建议当前内存状态使用。

## 八、suite 队列、并行、停止与续训

### 8.1 队列

以下需先完成真实资源测量并填实相应 suite 需求；原 null 清单会拒绝。

```powershell
& $py -I $cli suite plan --config "$c/suite-2h.json"
& $py -I $cli suite status --config "$c/suite-2h.json"
# 下行才真正启动队列，默认串行。
& $py -I $cli suite run --config "$c/suite-2h.json"
# 仅已测量且资源足够时允许一脑+一CNN。
& $py -I $cli suite run --config "$c/suite-2h.json" --parallel
```

8h 清单为 `suite-8h.json`，A3 候选清单为 `suite-A3-variants.json`。suite相对 `config` 和 `output` 均按suite文件所在目录解析，**不是一律按D:/fly项目根目录**。最新自带清单已将output修正为 `../runs_next/...`，例如suite-2h实际输出为 `D:/fly/experiment/runs_next/suite-2h`。你自建清单也可使用明确的绝对输出路径。

suite 会保存 `suite-plan.json`、每项 `suite-status.json`、有效配置、stdout/stderr；默认逐批执行，子进程失败不启动后续批次。状态来自持久化记录，不保证 PID 仍活着；不会自动清理旧锁，也不会杀进程。现有执行记录禁止隐式重训。

最新 CLI 已把 `suite plan --parallel` 传入计划器，可预览一脑＋一CNN批次；真正 `suite run --parallel` 仍会在执行前重新检查资源。suite 的 run 不是“自动从已有队列断点恢复”的命令。

### 8.2 受控停止

从训练输出取得真实 run 目录后，在另一个终端执行：

```powershell
$run = 'D:/fly/experiment/runs_next/把这里替换成实际train目录'
& $py -I $cli stop --run $run
# 也可以对实际suite输出根目录发请求，通知已知训练子目录并阻止下一批启动。
& $py -I $cli stop --run 'D:/fly/experiment/runs_next/实际suite输出目录'
```

stop 只写 `STOP`，不 terminate/kill；训练在完整宏转移/更新边界检查请求并落 checkpoint，不能中断正在进行的一次脑调用或优化。需要等待 `result.json`/最新完整 checkpoint，而不是看到 STOP 文件就认为保存完成。

### 8.3 恢复到新 episode，而非原游戏瞬间

```powershell
& $py -I $cli resume --run $run --config "$c/A5-2h.json"
# 将同路线正式2h run扩至累计8h，未改其他协议时可用：
& $py -I $cli resume --run $run --config "$c/A5-8h.json"
# 或显式指定完整checkpoint目录：
& $py -I $cli train --config "$c/A5-8h.json" --resume 'D:/fly/experiment/runs_next/实际run/checkpoint-实际编号'
```

保存内容包括模型/target/optimizer、DQN replay、学习器和训练 RNG、归一化/hash、步数、累计墙钟、epsilon schedule 所需计数及课程历史。恢复另建输出 run，保留累计统计，但 **重开 episode，reset 游戏/脑/视觉历史**，不恢复原位置与脑瞬时膜电位；中途半局不计作完整成功。

2h 扩到8h是总累计墙钟约8h，之前2h已花掉，通常剩约6h。新 `train A5-8h` 不带 resume 则是从头新训练，不能冒充续训。不要修改 seed、特征、算法、动作保持、奖励、课程等协议后强行续；来源、版本、文件 hash 漂移会拒绝，保留环境和源码快照。

load_checkpoint 允许 wall_hours/max_game_tics/output 变化，但课程 state 还严格绑定 `max_game_tics`，所以目前不要改变它恢复；尤其不能用16-tic smoke checkpoint直接接1000万tic正式配置。恢复 CLI 直接调用 runner，**没有自动走 suite.resume 的资源门禁**，恢复前也要人工重新检查内存和保存峰值。

runner 会检查本 run 和若干父目录的 STOP。父级 suite STOP 若未按你自己的停训意图处理，恢复出来的新 run 也可能立刻退出；确认已保存且确实要继续后，再处理对应 STOP 请求，不能盲目清理锁或别人的停止标记。

### 8.4 PPO 尾数据策略

当前唯一明确策略是：**每次周期 checkpoint 和最终停止都丢弃尚未更新的 rollout 尾部，累计到 `ppo_discarded_tail`**。不是保存后重算 `old_logp`，也不是恢复后把旧策略数据混入新 PPO。

已完整收集并触发更新的数据用采集时 `old_logp/value/next_value` 与边界计算；不足一批或预算到点的尾部可以丢弃，但必须看计数。默认 `checkpoint_every=2000` 是 decisions，不是 tics；与256 rollout不整除时，周期保存可能丢掉较长尾部。意外崩溃/更新中断只回上一个完整原子 checkpoint，`.incomplete` 目录不作有效恢复点。

## 九、冻结验证、选优和多 seed

### 9.1 预先固定的数据划分

默认 train 12 个条件布局，含三起点、左右镜像；val **12** 个 full-entry 条件，test **24** 个 full-entry 条件。train/val/test 使用互斥环境 seed 列表，配置会检查同 split 与跨 split 的实际 WAD 内容 hash 重复。它们主要是同类几何上的起点扰动/镜像/光照条件变化，不能包装成新几何、新地图泛化。

评估按布局索引循环使用该 split 的 seed 列表；不是12×3或24×3的笛卡尔积。修改配置后应在训练开始前冻结，不要看 test 再挑配置。

顺序：固定 val 前4条件快速筛查→入围者完整 val12→冻结路线、超参和训练 seed 方案→最终 test24。quick 仅作为筛查，`compare` 拒绝 quick 结果进入正式比较。

```powershell
$ckpt = 'D:/fly/experiment/runs_next/实际run/checkpoint-实际编号'
& $py -I $cli evaluate --checkpoint $ckpt --split val --quick
& $py -I $cli evaluate --checkpoint $ckpt --split val
# 仅最终锁定后执行，不反复用test调参。
& $py -I $cli evaluate --checkpoint $ckpt --split test
```

脑模型完整评估可能数小时；12或24局×最多2000tics，还要逐tic全脑。先量一次短测吞吐，把 val4/val12/test24 的预计与实际耗时分别记录，不自动每个 checkpoint 跑全套。

### 9.2 决策标准

主排序由你依据原始评估逐局数据完成：

1. full-entry 成功率，左右分别检查；
2. 仅成功局的成功耗时，失败局数量必须同时报；
3. 全局 max progress 分布/中位数、墙碰数；
4. 前进与转向 tic 比例、停滞/绕圈倾向；
5. 同墙钟的性能、同样本数的性能分开；校准、候选搜索、评估成本另记。

最新 `compare` 已将 corridor 排序改为：**成功率降序→平均最大进度降序→成功局平均耗时升序**，return仅旁列、不参与决胜。它与上文建议的人工层级略有不同（进度在成功耗时前），应读取输出的ranking及逐局数据。动作比例、左右覆盖、训练seed不确定性仍需综合检查，不能把单次榜首自动当作正式通关冠军。不要重蹈 A0 正 return、0通关的误判。

开发继续条件：真实环境/存档边界健康，loss/Q/梯度有限，确实发生更新，有前进与课程覆盖。长训扩展条件：val4 有可重复的通关或显著进度改善，完整val12不只单侧偶然成功。停止诊断条件：持续NaN/发散、动作彻底坍塌、课程永远不晋级、吞吐/内存失控，或多次训练完整入口仍无任何进展。门槛应在看 test 前锁定；这里不给未实测数据编一个必胜成功率。

### 9.3 三类比较与命令

```powershell
& $py -I $cli compare 'D:/fly/某A5完整val/result.json' 'D:/fly/某A6完整val/result.json' --mode performance
& $py -I $cli evaluate --checkpoint $ckpt --split val --intervention brain_zero
& $py -I $cli evaluate --checkpoint $ckpt --split val --intervention brain_permute
& $py -I $cli evaluate --checkpoint $ckpt --split val --intervention black
& $py -I $cli evaluate --checkpoint $ckpt --split val --intervention scramble
& $py -I $cli evaluate --checkpoint $ckpt --split val --policy random
& $py -I $cli evaluate --checkpoint $ckpt --split val --policy untrained
& $py -I $cli compare 'D:/fly/同checkpoint正常val/result.json' 'D:/fly/同checkpoint脑置零val/result.json' --mode intervention
```

- `performance`：允许不同模型/算法/训练seed，同任务、评估case、奖励与来源约束；动作协议不同则隔离分榜，不能跨榜宣称公平胜负。实际训练tics可以不同，会标识是否相同；这不是自动完成等样本重训。
- `intervention`：固定 checkpoint 比正常输入、黑屏、置乱或脑分支控制；随机/未训练策略可作参照。
- `connectome`：比较器有严格入口，要求显式 real/rewired 同route及匹配协议；**当前 v2 配置没有 arm 字段，也没有真实/重连脑训练开关**，不能把该比较器入口说成已实现一键拓扑实验。旧严格四臂保留在旧栈。A1/A2或A5/A7不合格替代严格连接组对照。

新配置只支持 corridor；combat 指标虽有比较函数分支，不能给出已验证的 combat 训练承诺。未来真正接入后应看 kills/hits/survival/damage，不以恒false的corridor success排序。

### 9.4 多训练 seed 与多条件的不确定性

优胜者至少2—3个独立训练 seed，例如41027/41028/41029；这指分别初始化与训练的三份模型，不是同一模型在三个环境seed上各评估一次。当前配置中的 `seed` 是学习器随机性，`train_seeds` 是环境种子列表，两者别混淆。需要为每个训练seed准备独立配置与输出，CLI没有 `--seed` 快捷参数。

按每个训练seed分别报告val12/test24，再报告均值、范围和逐case结果；seed方差与case方差分别描述。不凭一次通关判定路线胜出，也不把24个case当作24次独立训练。任何A3候选、校准改动、超参尝试及失败都登记成本，避免反复挑val造成隐性过拟合。
