# 老师训练改进方案 v3.2（3-4 小时预算版）

> 状态：待用户批准。批准后按两阶段执行。
> 依据：老师 v1/v2/v2-ext 终验数据（600 tics×3 seeds）+ 训练日志命中统计 + 外部审计第 9 节建议。
> v3.2 相对 v3.1 的变更：① 总执行预算拉长到 3-4 小时；② 观测改为"灰度+运动差分"2 通道（1536 维，弃 4 帧堆叠）；③ 弃 warm start（维度不兼容），从头训练；④ 明确"训 3 个种子候选、评估选 1 个唯一老师"。

## 0. 结论先行

- 实测已否定：fire_bonus=0.1（乱开火、击杀退化）、corridor→combat 迁移（无增益）、lr 衰减到 1e-5（续训固化坏策略）。
- v3 核心：奖励重构（命中反馈 + 受伤加重）、观测升级（灰度+差分）、cosine 学习率、直接长训目标场景。
- **多老师策略**：一个 PPO 配置 → 训练 3 个独立种子（候选）→ 统一协议终验 → **选最优 1 个作为唯一老师**（蒸馏目标必须单一；不集成、不平均）。
- **预算**：阶段 1（奖励快筛）+ 阶段 2（胜者长训）+ 终验 ≈ 3.5-3.8 小时墙钟。

## 1. 统一评估协议（评估老师好坏的唯一标准）

每次版本比较（v1/v2/v3/学生）**必须**使用同一协议：

| 项 | 设定 |
|---|---|
| 主场景 | combat_survival（本地 cfg） |
| 泛化对照场景 | defend_the_center（vizdoom 自带） |
| 单局时长 | 600 tics（10 秒），满血不死则到 600 截断 |
| 随机种子 | **5 个游戏种子**（41027-41031），全部独立 episode；训练种子与游戏种子解耦 |
| 策略采样 | 贪心（argmax，无探索噪声） |
| 报告口径 | mean±std over seeds + 每 seed 明细 |

**记录指标（7 项，缺一不可）：**

| 指标 | 定义 | 判断标准 |
|---|---|---|
| 平均击杀数 | KILLCOUNT 增量 | 验收 ≥4 |
| 平均存活时间 | episode tics | 验收 ≥545（v1 水平） |
| 平均受伤量 | ΣΔhealth 与终值 health | 健康应为正 |
| 命中率 | HITCOUNT 增量 / 开火帧数 | 验收明显高于 1% |
| 弹药效率 | 弹药消耗 / 击杀数 | 乱射惩罚指标 |
| 动作分布 | 12 类动作频率（含开火占比） | 开火占比>60% 判乱射嫌疑；多样性≠能力 |
| 稳定性 | seeds 间 std | std 大→降权，报告 |

**训练中 eval**：每 5000 步，5 game seeds × 600 tics（老师不跑脑仿真，单次约 1-2 分钟）。

## 2. 奖励消融（每次只改一个因素）

| 变体 | 公式 | 改动因素 | 状态 |
|---|---|---|---|
| A 原始（v1） | Δkills×10 − Δhealth×1 | 基线 | 已测：2.67±1.25 |
| B +开火塑形（v2） | A + fire_bonus=0.1 | +开火奖励 | 已测：2.00→1.67，**否定** |
| **C +命中奖励** | A + ΔHITCOUNT×1 | +命中反馈 | 待测（v3 候选） |
| **D +受伤加重** | Δkills×10 − Δhealth×2 | health 权重×2 | 待测（v3 候选） |
| **E 完整** | Δkills×10 − Δhealth×2 + ΔHITCOUNT×1 | 组合 | 待测（v3 主推） |

筛选准则（权重递减）：击杀 → 存活/健康 → 命中率 → 弹药效率 → 稳定性。E 与 C 差距不大时取改动更少的 C。

## 3. 观测与网络

- **观测：灰度 + 运动差分（2 通道）**，24×32 灰度 + |Δ帧| 差分 → 1536 维
  - 理由①：运动信息直接可见（单帧无运动是 v1 上限 2.67 的结构性原因）；
  - 理由②：成本约为 v1 的 2 倍（4 帧堆叠 3072 维会超预算）；
  - 理由③：**与学生视觉前端 v4_agc_motion（AGC+运动差分）信息结构对齐**——老师用到的运动信息学生端同样存在。
- 网络：MLP **1536→256→128**（保持 v1 的隐藏宽度，只扩输入层；低分辨率任务容量足够）
- 学习率：3e-4 起步，**cosine 衰减到 3e-5**
- rollout 4096 / mini-batch 512 / epochs 10 / gamma 0.99 / lam 0.95 / clip 0.2 / entropy 0.02
- **从头训练**（弃 warm start）：v1 是 768 维输入，与 1536 维不兼容，权重拼接引入隐患；预算充足（3-4h）足以从头学出好老师，靠奖励稠密化提速。

## 4. 两阶段执行流程与预算（总墙钟 3.5-3.8h）

```
阶段 1 · 奖励快筛（≈1h，3 进程并行）
  C / D / E 各训练 1 份 × 60k 步（每份约 50 min，3 份并行 → 墙钟 ~55 min）
  每份配 3 个训练种子候选 → 60k 终验（5 game seeds × 600 tics）
  → 按筛选准则选出最优奖励公式

阶段 2 · 胜者长训（≈2.8h，3 进程并行）
  最优奖励 × 3 个训练种子候选 × 200k 步（每份约 2.8h，3 份并行 → 墙钟 ~2.8h）
  → 3 候选全部保留 checkpoint

终验与选老师（≈30 min）
  统一协议：5 game seeds × 600 tics × 2 场景 × 7 指标
  → 3 候选种子中选终验最优 1 个 = 唯一老师 teacher-v3-best
  → 输出对比表：v1 / v2 / v3 全指标
```

**验收（v3 全部满足）**：击杀 ≥4｜存活 ≥545 tics 且健康为正｜命中率明显高于 1%｜弹药效率优于 v2｜跨 seed 稳定。

**后备路径**：若阶段 1 三个变体终验击杀全部 ≤1.5（奖励改动均无益），阶段 2 改为 A 奖励 + 新观测（=只测观测升级的单独收益），不浪费预算。

## 5. 第三步：老师能力与学生能力分开评价

| 问题 | 评价方式 | 判定 |
|---|---|---|
| 老师强不强？ | 统一协议独立评估（老师不看脑） | 7 指标 vs 验收线 |
| 学生能不能复现？ | 同协议跑学生（3 seeds，学生跑脑较慢）+ 留出集动作一致率 | 闭环击杀 vs 老师；一致率 ≥60% 目标 |
| 弱在哪一环？ | 对比矩阵 teacher/student/random/v1-student | 老师弱→回训练；老师强学生弱→查读出/蒸馏/时间对齐 |

信息约束：老师可用完整信息（含 HITCOUNT 内部变量），**学生输入只含脑读出活动**，不得混入敌人坐标等游戏内部信息。

## 6. 训练效率手段（又快又准）

1. **奖励稠密化**：ΔHITCOUNT 命中 +1（立即、稠密）替代稀疏击杀——收敛速度的主要提升
2. **观测 2 通道差分**：运动信息直接可见，省去堆叠帧的维度浪费（1536 vs 3072，训练快一倍）
3. **多种子并行**：阶段 1/2 均 3 进程并行（ViZDoom 多实例互不依赖），墙钟不随种子数线性增长
4. **快筛→长训**：60k 小预算淘汰坏奖励，把 200k 预算留给已验证的奖励
5. **评估协议统一**：7 指标 + 5 seeds + 2 场景一次定死，杜绝"单次最佳成绩"误导
